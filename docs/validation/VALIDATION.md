# Validation and Testing Strategy

Run with `python -m pytest` from the repository root. `pytest.ini` turns `RuntimeWarning` into an error, so numerical warnings (overflow, invalid values) fail the suite instead of being ignored.

## Test layers

| Layer | Folder | What it proves |
|---|---|---|
| Unit | `tests/unit` | each algorithm against closed forms: boosts, invariant mass (vs a 50-digit reference), helix geometry, Crystal Ball normalisation and continuity, unaliased convolution, data validation rules |
| Property-based | `tests/unit` (Hypothesis) | invariants over random inputs: Lorentz invariance of mass, boost∘boost⁻¹ = 1, the helix stays on its circle and starts at the vertex |
| Integration | `tests/integration` | production → decay → detector → fit → selection; same seed gives the same result; parallel equals serial; configuration round trip; provenance record; data–simulation comparison on the real file |
| Physics validation | `tests/physics_validation` | known answers end to end: exact reconstruction with an ideal detector; Gluckstern resolution; scattering floor vs the analytic estimate; Collins–Soper 1 + cos²θ recovered with an independent formula; unpolarised quarkonia; production spectra match their CDFs; masses recovered by fits; curvature unbiased; toy pulls of unit width |
| Visualization | `tests/visualization` | display geometry equals the detector configuration (radii, half-lengths, ±z disks, beam pipe inside the first layer); hit and track coordinates equal the simulation arrays exactly (replayed random stream); with an ideal detector, true and reconstructed paths coincide and hits lie on their surfaces; residual magnification is exact; PyVista meshes carry those coordinates; event actors are replaced, not accumulated; visibility toggles persist across events; PyVista loads off the GUI thread while the event loop keeps running (fresh interpreter) |
| Regression | `tests/regression` | fixed-seed selected counts, mean and RMS of the mass for all three processes (relative tolerance 1e-7 and 1e-5) |

All 28 checks from the original suite were kept. Each is marked `# original test N` where it now lives. Two expectations changed for documented reasons:

1. **The fit test now uses the likelihood fitter** (ADR-8), and "fit recovers mass" uses a detector without scattering. With scattering, the second-order resolution shift of about (3/8)Σσ² is real physics, not a fitter error, and is tested separately in `test_curvature_is_unbiased_and_pt_bias_follows_resolution`.
2. **The Gluckstern test uses the exact constant 0.299792458** in both the fit and the formula, instead of 0.3.

## Numerical checks

| Concern | Guard |
|---|---|
| Cancellation in m² for collinear pairs | stable formula; mpmath test |
| β → 1 in boosts | raises for \|β\| ≥ 1; γ²/(γ+1) form is safe at β = 0 |
| Loopers (r > 2R) | barrel crossings require r < 2R; disks require s < πR (tested) |
| Tracks with pz ≈ 0 | disk crossings guarded against division by zero |
| Crystal Ball tail overflow | tail evaluated in log space |
| Convolution aliasing | kernel aligned on the grid (tested) |
| Singular fits | fewer than `min_hits` → track not reconstructed; non-positive-definite Hessian → fit flagged not converged |
| Empty bins | Poisson likelihood handles n = 0 (tested) |

## Independent derivations used as cross-checks

- **Collins–Soper angle:** generated with frame axes, recomputed from the lab four-vectors with the light-cone formula.
- **Momentum resolution:** simulated vs the Gluckstern closed form (no material) and vs the uniform-scatterer estimate (material).
- **Z line shape:** generated by numerical inverse CDF and fitted by numerical convolution. Both use the same s-dependent BW; the fixed-width alternative shows the expected ~34 MeV convention shift.
- **pT bias:** observed ⟨pT⟩ shift compared with var(1/pT) from the same tracks.
